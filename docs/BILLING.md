# 费用记录与分摊

成员承担所负责 Agent 任务的费用与结果责任。一个 Agent 可以执行多个人的任务，因此费用按每次任务的负责人记账，再汇总到 Agent 和成员。费用归属不决定模型、API 凭证或运行机器，也不会改变人工审核节点的行为。

## 使用方式

1. 重新导出新版运行包并执行。运行时自动写出 `logs/usage-report.json`。
2. 在同一个项目打开 **Costs & split**，导入该文件。可以在运行过程中及完成后多次导入；同一尝试只保留一条，新报告更新已有记录。
3. 在 **Execution details** 核对每次执行的金额、币种及账单依据。默认归当时的负责人承担；共用任务可选择 **Shared equally** 并指定参与人。
4. 用 **Add shared cost** 补录规划、订阅或其他共用费用，选择参与人后均摊。已经计入某次执行的费用不要再次补录。
5. 在 **Member split** 查看各人的自有 Agent 费用、共用费用和最终金额。导出明细 CSV 或分摊 CSV，也可导出账本 JSON 备份。

## 自动记录什么

每个任务的每次尝试分别保存运行 ID、任务、Agent、执行时负责人、提供商、模型、开始与更新时间、执行状态以及输入/输出/缓存 token。API 每轮返回用量后会立即保存；后续结果格式错误、工具错误或重试不会抹去已知消耗。CLI 累计用量更新同一次记录，不会把累计值重复相加。审核后继续执行不会重复计费。

输入 token 的统一含义包含缓存读取及创建部分，缓存字段只是其中的明细，不能再加到总输入上。多轮调用缺失部分字段时，`partial` 表示已知小计；`null` 表示没有可靠数字。`reported` 表示执行器已报告输入输出用量，不表示提供商账单已核对。旧运行没有账本时标记为 `legacy`，模拟执行标记为 `simulated`，不据此推算消费。

只有执行器明确提供金额时才展示估算，例如 Claude CLI 的估算美元金额。没有维护静态单价表，也不把订阅 token 自动换算成按量付费。API 报错但没有返回用量时，费用可能仍发生；页面保留未知状态，由使用者查账后确认。

## 哪些金额参与分摊

只有人工确认的执行金额和人工添加的共用费用参与分摊。估算单独显示，不加入应分摊金额；模拟执行不能确认费用，仍在运行的尝试要等结束后再确认。查账确认的零金额有效，未查明的金额保持未知。

导入更新报告后，如果已确认记录的用量、状态、提供商、模型或估算发生变化，原确认金额会保留并标为需要重新核对；核对前暂时不计入分摊。单纯更新时间变化不影响确认。新报告不能更改既有记录的运行、Agent、负责人或尝试编号；过期报告不能覆盖新数据。

支持 USD、CNY、EUR、GBP，币种分别汇总，不自动换汇。金额最多六位小数，计算用整数微单位，避免二进制浮点误差。共用金额先按参与人数均分；微单位余数按成员 ID 的固定顺序分配。最终按每个币种的总确认金额四舍五入到分，各成员先取整分，再按小数余数由大到小补齐差额，相同余数按成员 ID 排序。因此各人最终金额相加与项目结算总额完全一致；明细小计可能保留超过两位小数。

## 保存与恢复

运行时的 `logs/run-state.json` 保存原始用量账本，`logs/usage-report.json` 是供界面导入的摘要，不包含提示词、结果正文或凭证。报告导出失败会留下警告，不影响已保存的主状态；后续状态保存会重试导出。

费用账本保存在当前浏览器，以项目 ID 隔离，独立于工作流 JSON 和下载的运行包。**导出工作流不等于备份费用账本**。换设备时先在新设备导入相同项目 ID 的工作流，再导入账本 JSON。导入账本会替换当前账本，页面会要求确认；用量报告只合并执行记录。删除项目同时删除本机对应账本。

损坏的本机账本不会被静默覆盖，页面支持导出原始数据后恢复。浏览器保存失败时会提示未保存，当前页面仍可导出；离开页面前应先导出。其他标签页的更新会同步，发生未保存编辑冲突时不会自动覆盖。此功能没有云同步、账号验证、付款或真实账单连接。

单份用量报告最多 1 MiB，账本最多 8 MiB；最多 5,000 条执行记录、1,000 条共用费用，每条共用费用最多 50 位参与人。超限、其他项目的数据或结构无效的文件整份拒绝，不做部分导入。导出的 CSV 对可能被表格识别为公式的文字做转义。
